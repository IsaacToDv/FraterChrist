# Contribuir a FraterChrist

FraterChrist prioriza cambios pequeños, comprensibles, documentados y verificables. El proyecto también se utiliza para aprender: no se espera que quien contribuye conozca todo el stack de antemano.

## Flujo sugerido

1. Revisa el [README](README.md), los [requisitos](docs/REQUISITOS.md), la [arquitectura](docs/ARQUITECTURA.md) y el [plan de aprendizaje](docs/PLAN-APRENDIZAJE.md).
2. Busca un Issue existente antes de crear otro.
3. Elige una tarea pequeña con un resultado comprobable; evita trabajar en varios Issues principales a la vez.
4. Lee los criterios de aceptación y registra dudas o decisiones importantes.
5. Crea una rama descriptiva, implementa el cambio y ejecuta las pruebas pertinentes.
6. Abre un Pull Request enlazando el Issue. Resume el problema, la solución, las pruebas ejecutadas, el aprendizaje y las limitaciones.
7. Cierra la tarea solo cuando la evidencia exista y sea reproducible.

## Criterios

- No incluyas contraseñas, tokens, claves API ni archivos `.env`.
- No añadas dependencias sin justificar su necesidad.
- No declares una funcionalidad completada sin probarla.
- Comprueba entradas inválidas, errores y permisos cuando correspondan.
- Verifica las licencias de dependencias y recursos.
- Registra la revisión de aportes relevantes de IA en `docs/USO-RESPONSABLE-DE-IA.md`.
- Mantén las discusiones respetuosas y centradas en el proyecto.

## Aprender con ayuda de IA

Puedes usar herramientas de IA para investigar, comparar alternativas o revisar errores. Antes de integrar una sugerencia, comprueba que la entiendes y verifica el resultado con pruebas o documentación fiable. No presentes código generado que no puedas explicar como evidencia de dominio técnico.

## Pull Requests

Un PR debería responder: ¿qué problema resuelve?, ¿qué cambió?, ¿cómo se comprobó?, ¿qué aprendí? y ¿qué queda pendiente?
