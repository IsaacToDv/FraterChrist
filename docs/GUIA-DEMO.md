# Guía para la demo técnica

La demo debe mostrar el estado real del repositorio, no pantallas simuladas como si fueran producto terminado.

## Guion sugerido (3–5 minutos)
1. Problema y alcance (30 s).
2. Arquitectura y motivo del monolito modular (45 s).
3. Caso de uso: un ejemplo válido y otro inválido (60–90 s).
4. Datos, migración y pruebas (45 s).
5. Decisión técnica, error encontrado y siguiente mejora (45 s).

## Antes de grabar
- [ ] Las instrucciones funcionan en un entorno limpio.
- [ ] No aparecen credenciales ni datos personales reales.
- [ ] Los comandos y resultados se ejecutaron realmente.
- [ ] El video distingue lo implementado de lo planificado.
- [ ] Se enlazan commit, pruebas y documentación.
- [ ] La demo se centra en el problema técnico y el aprendizaje.
